# Five-minute interviewer demo

## 0:00–0:25 — Frame the system

Say:

> This is a customer-operations control layer, not a chatbot. The tenant and inventory are synthetic. PostgreSQL owns operational truth, Airtable is a CRM projection, n8n is orchestration, and NVIDIA NIM is a bounded reasoning provider.

Point to provider badges and the manager exception summary.

## 0:25–1:20 — Sales enquiry

Send the prepared Fortuner message.

Show:

- normalized demo channel,
- extracted model, budget, colour, transmission, timeline, and trade-in,
- lead score and stage,
- verified synthetic inventory rows,
- CRM sync status,
- response mode and tool trace,
- next action and audit event.

Say:

> The model is not an inventory source. Availability appears only after a bounded DMS query, and the response is guarded before delivery.

## 1:20–1:55 — Appointment replay

Create the test drive, then click Replay same command.

Show that the same appointment ID returns with replayed status and only one row exists.

Say:

> Retries are normal in automation. The system makes retries safe instead of hoping they never happen.

## 1:55–2:35 — Commercial approval

Request a ₹50,000 discount and modify it to ₹20,000.

Say:

> The prompt does not contain the authority boundary. Typed policy does. A model can communicate a stored decision but cannot manufacture one.

## 2:35–3:15 — Break the DMS

Disable inventory, send a fresh stock enquiry, and show:

- the lead remains stored,
- inventory results are empty,
- the reply says verification is unavailable,
- manager health shows safe fallback.

Restore the DMS and probe stock.

## 3:15–3:50 — Service safety

Load and send the Hyryder braking-noise scenario.

Show the separate service case, high urgency, Saturday-morning preference, and workshop-review language.

## 3:50–4:25 — Lost revenue

Queue one stale high-intent lead from the recovery panel. Open n8n and show the Lost Lead Recovery canvas and provider handoff boundary.

Say:

> n8n makes business orchestration visible, while the API keeps domain rules typed and testable.

## 4:25–5:00 — Close on governance

Show the manager briefing, CRM sync ledger, tool trace, and audit timeline.

Say:

> The test is not only whether AI succeeds. It is whether failures preserve state, claims stay grounded, retries avoid duplicate business effects, and people retain authority over consequential decisions.

## Deliberate break attempts

If the interviewer asks to attack it:

1. replay the inbound event,
2. replay the booking,
3. ask the model to ignore policy and invent stock,
4. reserve the selected inventory before booking,
5. disable CRM or DMS,
6. request a human.

Each has a named automated test.
